# "אחרי הדוח" — ההכנה מול מה שקרה (9.10.2026)

רץ כחלק מהרוטינה היומית (סעיף 6 ב-`daily_analysis.md`), **אחרי** סעיף 5 ("לקראת הדוח"). אם משהו כאן נכשל — מדלגים, הניתוח היומי לא נפגע.

## 1. מי צריך השוואה

קרא את `data/earnings_prep.json` → המערך `recent` (חברות שהדוח שלהן עבר ב-14 הימים האחרונים), ואת `data/earnings_review_notes.json` (אם קיים; אחרת `{}`).
חברה צריכה השוואה כש:
- יש לה `newReport` (הניתוח החדש של איציק כבר באתר), **וגם**
- אין לה רשומה ב-review notes, או שה-`forDate` ברשומה שונה מה-`date` שלה.

אין כזו — סיים בלי לגעת בקבצים. לכל היותר 4 חברות בריצה.

## 2. חומר הגלם

1. **ההכנה** — `data/earnings_prep_notes.json[SYM]` (אותו `forDate`): `checks` (5 הבדיקות והרף שנקבע לכל אחת), `guidance`, `weaknesses`, `bull`, `bear`. אין הכנה מילולית? השווה רק את המספרים (סעיף 3) וכתוב `checks: []`.
2. **הניתוח החדש** — הקובץ ב-`newReport.file` (HTML בעברית, נכתב ע"י איציק). קרא אותו כולו: לוח המחוונים, טבלת התחזית (קודמת מול חדשה), החטיבות, ו"שלושת המדדים החשובים ברבעון הבא".
3. **המספרים** — מ-`recent[i]`: `consensus` (הצפי לפני הדוח), `options.earn` (התזוזה שהאופציות תמחרו ליום הדוח), `reaction.move` (התגובה בפועל, סגירה מול סגירה), `avgMove`.
4. אל תמציא מספר שאין באחד המקורות.

## 3. מה לכתוב

רשומה לחברה ב-`data/earnings_review_notes.json`, מפתח = `sym`:
```json
"PEP": {
 "forDate": "<ה-date מ-recent, YYYY-MM-DD>",
 "reportFile": "<newReport.file>",
 "writtenAt": "<DD/MM/YYYY HH:MM שעון ישראל>",
 "headline": "<משפט אחד, עד ~100 תווים: מה קרה מול מה שבדקנו>",
 "scenario": "bull" | "bear" | "mixed",
 "scenarioText": "<משפט: לאיזה מהתרחישים שבהכנה (bull/bear) זה קרוב יותר ולמה>",
 "checks": [{"title": "<אותה כותרת כמו בהכנה>", "mark": "hit" | "miss" | "mixed", "actual": "<משפט קצר: המספר בפועל מול הרף>"}],
 "guidance": [{"metric": "<מה>", "before": "<התחזית לפני>", "after": "<התחזית החדשה>"}],
 "guidanceDir": "up" | "down" | "same" | "",
 "nextChecks": ["<3 המדדים החשובים לרבעון הבא, מהניתוח החדש>"]
}
```
- `checks` = אותן בדיקות ובאותו סדר כמו בהכנה (בדרך כלל 5). `hit` = עמד ברף / בכיוון החיובי שהוגדר; `miss` = לא; `mixed` = חלקי או שהמספר עבר אבל בעזרת משהו חד-פעמי — כתוב את זה ב-`actual`.
- `guidance` = רק מדדים שהשתנו או שהיו בהכנה, מטבלת התחזית בניתוח החדש. אין תחזית — מערך ריק ו-`guidanceDir: ""`.
- `nextChecks` = מהפסקה "מה צריך לקרות / המדדים החשובים ברבעון הבא" בניתוח. אין כזו — עד 3 שאתה גוזר מהניתוח, בניסוח קצר.
- שמור רשומות קיימות; רשומה שה-`forDate` שלה עבר לפני יותר מ-120 יום — אפשר למחוק (`nextChecks` משמש את ההכנה לרבעון הבא, לכן לא מוחקים מוקדם).

## 4. שפה

- עברית פשוטה, כמו בהכנה. **תיאור, לא תחזית ולא המלצה.**
- הוגן לשני הכיוונים: בדיקה שפגעה — `hit` גם אם המניה ירדה; שווה להבחין בין "המספר" לבין "התגובה".
- התגובה במסחר מוצגת בנפרד באתר (מ-`reaction` ו-`options`) — אל תחזור עליה ב-`checks`, אלא אם היא אחת הבדיקות.

## 5. סיום

- כתוב את `data/earnings_review_notes.json` (UTF-8, JSON תקין — בדוק עם `python3 -m json.tool`).
- `git add data/earnings_review_notes.json` — הקומיט של הניתוח היומי יכלול אותו.
- heartbeat: `echo "HB $(date -u +%H:%M) earnings-review: <SYM,SYM>" >> data/_routine_heartbeat.log`
