# דוח הרוטציה הסקטוריאלית השבועי — הוראות לרוטינת nidam-rotation-weekly

גוף ההוראות של הרוטינה (הפרומפט ברוטינה הוא עטיפה קצרה שקוראת את הקובץ הזה; ראו `docs/routine-rotation-weekly.md`).
שינוי בתוכן הדוח נעשה כאן בלבד. גרסה 1 — 10.10.2026; גרסה 2 (מבנה הדוח החדש, §4) — 31.10.2026.

אתה כותב את **המילים** של דוח "לאן זרם הכסף השבוע?" — דוח רוטציה סקטוריאלית שבועי לפי מתודולוגיית Barchart (John Rowland), בעברית פשוטה, לקורא שאינו מכיר את השיטה. **המספרים לא שלך:** `scripts/build_rotation.py` מחשב הכל מקובצי ה-CSV שגרוק מעלה לדרייב (תשואות, דירוגים, רוחב, עוצמה מול השוק, ציונים, רביעים, המכ"ם, מפת החום). אתה קורא את התקציר שלו, כותב `narrative.json`, והסקריפט מרכיב את ה-HTML ומעדכן את ההיסטוריה. **כל מספר, אחוז, שם ורמה — מהתקציר ומ-`week.json` בלבד.** פרט שאין לו מקור מושמט, לא מנוחש.

## 1. השער — האם לרוץ עכשיו
הרוטינה רצה בשבת בבוקר. כל התנאים עצירים; כשעוצרים — לא כותבים כלום ולא דוחפים (חוץ משורת HB).

**מ-24.10.2026 אין הורדה מהדרייב** (איציק: "חבל על הטוקנים" — ההורדה כ-base64 דרך המחבר נתקעה פעמיים). הקבצים מגיעים לריפו מהמייל של גרוק (`Rotation – DD.MM.YYYY`, 20 צרופות) דרך `scripts/relay_rotation_mail.py` ב-Action, ל-`data/rotation/D/`. **אל תשתמש בכלי Google Drive גם אם יש לך אותם.**

1. `D` = התאריך של היום (שבת, `date +%F`). אם היום אינו שבת (הרצה ידנית לבדיקה) — רשום `echo "HB $(date -u +%H:%M) rotation: test run ok (not saturday, repo+push work)" >> data/_routine_heartbeat.log`, commit ל-log בלבד, דחוף, וצא. כך הרצה ידנית באמצע השבוע מוכיחה שהריפו מחובר והדחיפה עובדת.
2. אם `data/sectors/sectors-D.html` כבר קיים **וגם** `data/rotation/index.json` מכיל רשומה עם `date == D` — הדוח של השבוע נכתב. צא.
3. `git pull --rebase origin main` ואז בדוק `data/rotation/D/`: חייבים 16 קובצי `hist_*.csv`, `breadth.csv`, `industry-group-rankings.csv`, `heatmap.csv`, `manifest.txt`. אין תיקייה או חסר קובץ — המייל עוד לא הגיע או נדחה. רשום `echo "HB $(date -u +%H:%M) rotation: no files in repo for D" >> data/_routine_heartbeat.log`, commit ל-log בלבד, דחוף, וצא.

## 2. בדיקה
```
python3 scripts/build_rotation.py check D
```
`check` נכשל (קוד יציאה ≠ 0, מדפיס מה לא בסדר: תאריך אחרון ≠ שישי, קובץ קצר, תשואה לא סבירה) → HB עם הסיבה, commit של ה-log, דחוף, צא. **אל תתקן נתונים ידנית.**

## 3. המספרים
```
python3 scripts/build_rotation.py compute D
```
מדפיס את התקציר: S&P ורוחב השוק, טבלת 11 הסקטורים (תשואות, דירוגים בחמישה אופקים, פער דירוגים, רוחב MA50 ושינויו, מצב CRS, ציון ורביע מול השבוע הקודם, ממוצעים), בין-שוקי (ריבית 10 שנים, דולר, נפט, זהב), המכ"ם (כניסות/יציאות לפי שינוי אלפא), מפת החום, לוח הדוחות לשבוע הבא, **והקריאות של השבוע הקודם** (לדין וחשבון). הפרטים המלאים ב-`data/rotation/D/week.json`. ההיסטוריה המלאה (עד 26 שבועות) ב-`data/sector_history.json` — קרא ממנה את השבוע הקודם (`weeks[-1]`: `recommendations`, `notes`, `lessons`, `earnings_season`, `sectors[*].industries_note`) ואת מצב הפוזיציות.

**המתודולוגיה** (קרא לפני הכתיבה): `docs/rotation/METHOD.md` — הציון, הרביעים, מצבי CRS, וכללי המשמעת (כלל השבועיים, היציאה המשולשת, הדוחות, הפרבולה, וטו CRS, השבוע השני גם לטריגר, עונת הדוחות).

## 4. המילים — `data/rotation/D/narrative.json` (גרסה 2, מ-31.10.2026)
**המבנה החדש** (איציק 24.10: הדוח הישן "מבולגן, עמוס וקשה לקרוא"; מוקאפ אושר): עמוד אחד בארבעה צעדים — (1) הרקע: ארבעה מדי מאקרו, (2) טבלה אחת ל-11 הסקטורים עם פסק דין, (3) מה השתנה השבוע — עד שלוש כרטיסיות "סיבה → תוצאה → אבל", (4) מה עושים — רק סקטורים שיש בהם פעולה. כל השאר מקופל. **דוגמה מלאה ועדכנית: `docs/rotation/narrative_v2_example.json`** (שבוע 13) — קרא אותה לפני הכתיבה, ושמור על אותה צורה. הסקריפט מצייר את המספרים (מדים, פסים, רוחב, סדר הטבלה); אתה כותב רק את המילים.

כתוב קובץ JSON אחד (UTF-8, ערכים עבריים, מותר HTML פשוט: `<b>`, `<span dir="ltr">` סביב מספר חתום). המפתחות:

| מפתח | מה | כללים |
|---|---|---|
| `version` | `2` | חובה |
| `week_no` | מספר השבוע למעקב | `weeks_in_history` בתקציר + 1 |
| `season_tag` | "" או "עונת דוחות Qn — שבוע N" | רק בעונה (§5) |
| `headline` | **משפט אחד** — ה-H1 של הדוח | הסיבה והתוצאה: "הריבית ירדה מתחת ל-5% והנפט בשיא — הכסף יצא מ… ונכנס ל…". עד ~140 תווים, בלי מספרים עשרוניים, בלי "יצאנו/נכנסנו". **המשפט הזה מופיע גם בבית ובסיכום השבוע** (`#rotation-summary.lead`) |
| `dek` | 2–3 משפטים מתחת לכותרת | המדד מול הרוחב, מי הוביל ומי נחלש, הטריגר הגדול של השבוע |
| `macro_effect` | `{us10y, oil, dxy, gold}` | לכל מד **משפט אחד**: "מה זה עושה לסקטורים" (`<b>` על המסקנה). המספרים, הכיוון והממוצעים מצוירים אוטומטית מ-`week.json` — אל תחזור עליהם. אם בכל זאת כותבים "מעל/מתחת לממוצע" — רק אחרי השוואת `close` ל-`ma20`/`ma50`/`ma200` של אותו מד (31.10: "הדולר מעל כל הממוצעים" כשהוא היה מתחת לממוצע 20) |
| `verdicts` | `{XLK: {...}, …}` — **כל 11** | לכל סקטור: `status` = `held` (מוחזק) / `cand` (מועמד) / `out` (בחוץ) · `cls` = `ok` (מאושר) / `warm` (מתחמם) / `bounce` (ריבאונד / מתחת לקו 200 / מכ"ם) / `broken` (נשבר / מפגר) — זה סדר הטבלה · `verdict` = 2–5 מילים ("מאושר — נגיסה", "מתחמם — 4 מתוך 5", "ריבאונד — מתחת לקו 200", "נשבר — יציאה מלאה") · `checks` = 4 סימנים בסדר קבוע **[מאקרו תומך?, חזק מול המדד?, רוחב מאשר?, שבועיים רצופים?]** מתוך `y` (כן) / `n` (לא) / `p` (חלקי או מתהפך — למשל רוחב שעולה אבל מתחת ל-50, עוצמה מול המדד חיובית אך יורדת) / `n0` (לא רלוונטי — למשל מאקרו לסקטור ניטרלי) · `note` = משפט-שניים עם המספרים שמנמקים (רמה מול ממוצע, רוחב, מי מדווח) |
| `changes` | רשימה של עד 3 `{cause, title, text, but}` | **סיבתיות**: `cause` = הגורם המאקרו/האירוע ("ריבית השוק ירדה מתחת ל-5%", "מטא וטסלה אכזבו"); `title` = התוצאה בסקטורים במשפט; `text` = המספרים (רוחב לפני→אחרי, מקומות, רמות); `but` = מה זה *לא* / מה עוד לא אושר (כלל השבועיים, קו 200, הפרבולה) |
| `frozen_note` | "" או משפט-שניים | בעונת הדוחות: מי מדווח השבוע (ענקיות + הפד/מאקרו) ו"כלל הדוחות גובר". מחוץ לעונה — "" |
| `actions` | רשימה — **רק סקטורים שיש בהם פעולה השבוע** (2–5) | `{etf, kind, rows}`: `kind` = `exit` / `enter` / `hold` / `watch`; `rows` = 2–4 זוגות `[תווית, טקסט]` — הראשון תמיד `"פעולה"` (מודגש), ואז `"למה"` / `"טריגר"` / `"הגדלה"` / `"ביטול"` / `"חזרה"` לפי הצורך. **כל פעולה עם רמה מדידה** (ממוצע מ-`week.json`, רוחב, נפט) ועם ביטול. ללא מניות בודדות. סקטור בלי פעולה (מכ"ם, "ממתינים") — לא כאן; הוא בטבלה |
| `three_numbers` | 3 × `{label, value, note}` | "שלושה מספרים לשבוע": הרמות שמכריעות (ממוצע 20 של הנפט, קו החזרה של הטכנולוגיה, ממוצע 20 של הריבית…). `value` = מספר כטקסט ("93", "7,210", "5.19%") |
| `accountability` | `[כתבנו, קרה, מאזן]` לכל קריאה של שבוע שעבר | מ-`prev_week.recommendations`. המאזן מתחיל ב-"✔ נכון" / "✔ חלקית" / "✘ פספוס" + למה. **כנות**: פספוס לפי הכללים הוא פספוס. הכותרת סופרת אותם אוטומטית |
| `acc_summary` | משפט מאזן + הלקח | |
| `industries` | `[סקטור, "תעשייה א · תעשייה ב", "+x% · −y%", הערה]` | 3–6 שורות (מקופל): הסקטורים שבהם המכ"ם/מפת החום מספרים משהו שהמדד לא מראה. פער בין מדד הסקטור (משוקלל-שווי) לתעשיות (שווה-משקל) הוא מידע |
| `ch3_sowhat` | משפט-שניים או "" | דגלי "חד מדי, מהיר מדי" (כלל הפרבולה) והחריגים |

| `notes` | פסקה אחת — תמצית השבוע למערכת (היסטוריה) | מה השתנה, מה נפתח, מה נסגר |
| `lessons` | רשימת לקחים (או `[]`) | רק לקח חדש, מנוסח ככלל |

**כללי שפה (מחייבים):** "ריבית השוק" (לא תשואות), "נקודת יציאה (סטופ)", "עוצמה מול השוק" / "מול המדד" (לא CRS בגוף הדוח), "חד מדי, מהיר מדי" (לא פרבולי). שפה מדודה: ירידה/היחלשות/נסיגה — לא "קריסה". ציוני רוטציה מספריים — לא בגוף הדוח (הם במדדי העומק אוטומטית), בגוף רק דירוגים ומקומות. כל פעולה עם טריגר וביטול, לא "קנה/מכור". מספר חתום בתוך משפט עברי — עטוף ב-`<span dir="ltr">`. **קצר:** `note` עד 2 משפטים, `text`/`but` עד 3, `dek` עד 3 — הדוח כולו נקרא בדקה.

**פסק הדין לפי הכללים, לא לפי הסיפור:** הרביע מהסקריפט (ציון × דירוג 6 חודשים) הוא מידע-רקע; `cls` ו-`checks` נגזרים מכללי המשמעת (`docs/rotation/METHOD.md`): כלל השבועיים → העמודה הרביעית; היציאה המשולשת → `broken` רק עם רוחב + מחיר + שפל; כלל הדוחות → `frozen_note` וגודל הפעולה; הפרבולה → "נגיסה"; וטו העוצמה מול השוק → `p` בעמודה השנייה. כשהרביע סותר — הטבלה לפי הכללים, וההסבר ב-`note`.

## 5. מודול עונת הדוחות
פעיל מהשבוע שלפני דוחות הבנקים הגדולים (אמצע ינואר/אפריל/יולי/אוקטובר) ~6 שבועות. לרוטינה **אין רשת** — הלוח מגיע מ-`earnings_next_week` (TradingView דרך האתר), ושאר הנתונים (ציפיות FactSet, מבחני תגובה) רק ממה שכבר בהיסטוריה. בעונה:
- `season_tag` = "עונת דוחות Qn — שבוע N"; סקטור שהכבדות שלו מדווחות בשבוע הבא = **מוקפא לכניסות** (ב-`positions` ו-`earnings_rows`); פוזיציה בו — "לא מגדילים".
- **מבחן התגובה**: לסקטור שהכבדות שלו דיווחו בשבוע שעבר — איך הגיב (תשואת השבוע + שינוי הרוחב): טוב+עולה = אישור · טוב+יורד = חלוקה · רע+עולה = ניקוי · רע+יורד = המשך. כתוב ב-`earnings_season.reactions` ובעמודת "למה" של הסקטור.
- `earnings_season` = `{week_of_season, next_week_frozen: [ETF], caution: [...], reactions: {...}, ...}` — שמור גם שדות שהגיעו מהשבוע הקודם (ציפיות וכד') אם עדיין רלוונטיים.

## 6. הרכבה, בדיקה ודחיפה
```
python3 scripts/build_rotation.py render D
```
בודק שהמפתחות החובה קיימים, כותב `data/sectors/sectors-D.html`, ממזג את השבוע ל-`data/sector_history.json` (אותו תאריך = החלפה), ומעדכן `data/rotation/index.json` (ה-Action של האתר מעדיף דוח מקומי על העותק מ-nidam-reports).
`render` בודק שכל המפתחות החובה של גרסה 2 קיימים (`headline`, `dek`, `macro_effect`, `verdicts` ×11, `changes`, `actions`) ומשבץ בסוף הדף בלוק `#rotation-summary` (lead = `headline`, זוגות הרוחב, רוחב השוק) — זה מה שהבית וסיכום השבוע קוראים.
בדיקה קצרה לפני הדחיפה: `python3 -c "import sys;sys.path.insert(0,'scripts');import build_weekly as b,json;print(json.dumps(b.sectors_block('<שישי>'),ensure_ascii=False)[:600])"` — חייב להחזיר `lead` ו-`marketBreadth`.
ואז:
```
echo "HB $(date -u +%H:%M) rotation written D week=<week_no>" >> data/_routine_heartbeat.log
git add data/rotation/D data/rotation/index.json data/sectors/sectors-D.html data/sector_history.json data/_routine_heartbeat.log
git commit -m "rotation: דוח הרוטציה D (שבוע <week_no>)"
```
ודחיפה לפי העטיפה. **לא** לדחוף את `raw/` (נמחק ב-decode). קובצי ה-CSV כן נשמרים בריפו (~550KB לשבוע) — הם המקור של ההיסטוריה.
