# "לקראת הדוח" — הוראות לכתיבת ההכנה (2.10.2026)

רץ כחלק מהרוטינה היומית (סעיף 5 ב-`daily_analysis.md`), **אחרי** שהניתוח היומי נכתב. אם משהו כאן נכשל — מדלגים, הניתוח היומי לא נפגע.

## 1. מי צריך הכנה

קרא את `data/earnings_prep.json` (נבנה אוטומטית כל רבע שעה ע"י `scripts/build_earnings_prep.py`) ואת `data/earnings_prep_notes.json` (אם קיים; אחרת התחל מ-`{}`).
חברה צריכה הכנה כש:
- `daysTo` בין 0 ל-8 (מדווחת בשבוע הקרוב), **וגם**
- אין לה רשומה ב-notes, או שה-`forDate` ברשומה שונה מה-`date` של החברה (הדוח הבא, לא הקודם).

אם אין אף חברה כזו — סיים את הסעיף בלי לגעת בקבצים. לכל היותר 4 חברות בריצה (המוקדמות ביותר קודם).

## 2. חומר הגלם לכל חברה

1. **הניתוח של הדוח הקודם** — הקובץ ב-`report.file` (HTML בעברית, נכתב ע"י איציק). זה המקור העיקרי: מה ההנהלה הבטיחה (תחזית/guidance), אילו מדדים הוגדרו כ"לעקוב", מה היה חלש, ואיך המניה הגיבה. קרא אותו כולו.
2. **המספרים** — מ-`data/earnings_prep.json` של אותה חברה: `consensus` (צפי האנליסטים לרבעון), `history` (4 הרבעונים האחרונים: בפועל מול צפי + `move` = תזוזת המניה ביום התגובה), `avgMove`, `options.earn` (התזוזה שהאופציות מתמחרות ליום הדוח), `targets`, `recs`, `revisions`, `price` (`since.chg` מול `since.spy` = מאז ערב הדוח הקודם).
3. **מה אמרנו אחרי הדוח הקודם** — `data/earnings_review_notes.json[SYM]` (אם קיים): `nextChecks` = שלושת המדדים שהוגדרו כחשובים לרבעון הזה. הם המועמדים הראשונים ל-`checks`, וכדאי לציין בהם את הרף מהפעם הקודמת.
4. אל תמציא מספר שאין באחד המקורות. בלי רשת — הכל מהקבצים.

## 3. מה לכתוב

רשומה אחת לחברה, מפתח = `sym`:
```json
"JPM": {
 "forDate": "<ה-date של החברה ב-earnings_prep.json, YYYY-MM-DD>",
 "reportFile": "<report.file>",
 "writtenAt": "<DD/MM/YYYY HH:MM שעון ישראל>",
 "thesis": "<משפט אחד, עד ~110 תווים: מה נבחן הפעם. לא תחזית>",
 "dek": "<2 משפטים: הקשר מספרי — הצפי מול הרבעון הקודם, מה המניה עשתה מאז הדוח מול S&P 500>",
 "guidance": [{"metric": "<מה>", "value": "<התחזית העדכנית>", "prev": "<התחזית שלפניה, או \"\">"}],
 "guidanceNote": "<משפט: איך נראה הרבעון הקודם מול התחזית, או \"\">",
 "checks": [{"title": "<2–4 מילים>", "text": "<משפט אחד: מה המספר, מה הרף, מה יחשב חיובי/שלילי>"}],
 "weaknesses": ["<3 משפטים קצרים — נקודות חולשה מהדוח הקודם>"],
 "bull": "<משפט: מה יחזק>",
 "bear": "<משפט: מה יחליש>"
}
```
- `checks` = **בדיוק 5**, לפי החשיבות. כל אחד עם רף מספרי מהניתוח או מהצפי כשיש.
- `guidance` = 2–5 שורות, רק מה שכתוב בניתוח. אין תחזית בניתוח — מערך ריק.
- שמור רשומות קיימות של חברות אחרות כמו שהן; רשומה של חברה שה-`date` שלה כבר עבר ביותר מ-30 יום — אפשר למחוק.

## 4. שפה (כמו בניתוח היומי)

- עברית פשוטה, בלי ז'רגון; מונח מקצועי נחוץ — הסבר בכמה מילים בפעם הראשונה (למשל "הכנסות ריבית נטו (NII)").
- **תיאור, לא תחזית ולא המלצה.** בלי "המניה תעלה", בלי אחוזי הצלחה. "מה יחזק / מה יחליש" — תנאים, לא ניבוי.
- אל תחזור על המספרים שהאתר כבר מציג בנפרד (צפי, אופציות, תגובות) אלא כשהם חלק מהטיעון.

## 5. סיום

- כתוב את `data/earnings_prep_notes.json` (UTF-8, JSON תקין — בדוק עם `python3 -m json.tool`).
- `git add data/earnings_prep_notes.json` — הקומיט של הניתוח היומי (שלב 3 בעטיפה) יכלול אותו.
- הוסף ל-heartbeat: `echo "HB $(date -u +%H:%M) earnings-prep: <SYM,SYM>" >> data/_routine_heartbeat.log`
